## 测试期间修复的问题

最初2次请求出现 SDK 包装的 TypeError，随后一次90秒读超时；更小输入对照再次出现 TypeError。错误堆栈定位到HTTP响应的Brotli解码器：新HTTP层调用 `process(..., output_buffer_limit=...)`，本机 `brotli 1.0.9` 仅接受位置参数。离线样例复现 `TypeError: process() takes no keyword arguments`。

统一客户端改为请求 gzip/deflate 后，小输入摘要在37.84秒内成功返回，接口报告输入2606、输出1028 tokens。该次测试最初把“记录中无提交”漏判为未保留“未提交”状态；核对实际摘要后修正判定规则并补回归测试，原报告仍保留原始结果。之后重新运行完整样例，所有检查通过。

- [修复前TypeError堆栈](../../.cache/summary-probe/20261008T075658340332Z/report.json)
- [小输入返回的实际摘要](../../.cache/summary-probe/20261008T080046023740Z/summary.json)

这个修复针对HTTP响应解码，不是对话摘要算法；没有改动系统Python依赖或关闭TLS验证。它不能证明此前所有TLS中断、超时或502都由同一原因导致，也不能保证服务商永不出现网络故障。
