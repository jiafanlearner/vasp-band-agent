# 提交后的定时检查

成功提交并取得真实 Slurm JobID 后，Agent 自动保存服务器、任务名、阶段和作业编号。交互式 Agent 运行期间，后台按间隔调用 `squeue`、`sacct` 只读检查；不调用模型、不消耗模型 token、不申请计算节点。

默认检查间隔为 **15 分钟**。自动模式下，AI 可以根据实际阶段、测试规模和运行时限，用 `recommend_job_check_interval` 提出 1–60 分钟的本次任务建议，并保存理由；没有建议时，程序按运行时限作粗略调整：不超过一小时为 5 分钟，至少八小时为 30 分钟，其余为 15 分钟。这些是检查频率建议，不是计算耗时或排队时间预测。手动设置优先，AI 不能重新开启操作者暂停的监控。

```text
/watch                 查看目标、状态、间隔和下次检查时间
/watch off             暂停定时检查，保留记录
/watch on              恢复定时检查
/watch interval 15     所有未结束目标固定每 15 分钟检查
/watch auto            恢复自动建议间隔，保持当前开启/暂停状态
/watch check           立即执行一次只读检查（暂停时也可使用）
/watch remove 123 hpc  移除服务器 hpc 的 JobID 123 监控，作业继续运行
```

`/watch interval` 不会重新开启已暂停的监控，需要时另用 `/watch on`。同一个 JobID 出现在多个服务器时，移除操作需指定服务器。`/watch` 指令无需模型接口，输入 `/watch ` 后可补全子命令。

周期检查只在状态变化、查询失败、查询恢复、结束或需要审阅时提示。相同错误不会反复刷屏，连续查询失败会逐步延长重试间隔，恢复后重新使用原检查间隔；查询为空、连接失败或未知状态均不会被当作完成。只有明确调度终态才停止该目标的检查。

每个目标绑定该阶段的真实提交回执，不会因提交下一阶段而跟随新的 JobID。数组逐项检查所有预期元素；父作业 COMPLETED 或部分元素完成不表示整个数组完成。监控只读取调度状态和已有工作流摘要，不生成科学验收、放行阶段、部署、取消、重交或提交下一阶段。调度 COMPLETED 只表示该作业结束；工作流是否通过验收需再查看真实输出和阶段审阅。

记录保存在工作区 `.job-monitor.json`，默认被 Git 忽略。新对话、模型切换和重启会重用同一工作区监控记录，但不继承任何提交授权。多个 Agent 进程同时打开该工作区时，只有一个后台检查进程拥有监控锁，避免重复查询。另一个进程的 `/watch check` 若无法取得检查锁，会返回没有检查目标；可到正在监控的窗口执行。

**必须保持 Agent 进程运行。** `/exit` 或关闭终端后检查暂停，集群作业继续运行；下次启动后恢复未结束目标的检查。本版未提供终端关闭后的独立常驻服务或系统通知。单次 `--prompt` 或独立提交 CLI 会保存已确认提交的监控记录，需启动交互式 Agent 才会定期检查。旧版已经提交但从未登记的作业不会被全服务器扫描导入；新版本返回该任务已确认提交回执时才会登记。

监控登记失败会单独提示，保留成功提交的真实 JobID；这不是提交失败，不应再次提交。

开发验证：

```bash
python -m pytest -q tests/test_job_monitor.py tests/test_job_monitor_polling.py tests/test_job_monitor_integration.py
```
