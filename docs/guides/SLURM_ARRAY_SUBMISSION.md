# 远程 Slurm 数组收敛提交

本功能仅用于远程、启用阶段检查点的 `convergence` 阶段。`submission_mode` 可选 `allocation` 或 `array`；未指定时保持旧默认 `allocation`。本机提交、旧版一次执行完整流程的任务，以及 `relaxation`、`scf`、`bands` 均不使用数组。

## 模式与资源含义

| 项目 | allocation | array |
|---|---|---|
| 提交方式 | 一个资源分配中运行独立测试 | 一次 `sbatch` 提交数组，每项独立排队 |
| `parallel_tests` | 分配内同时运行的测试数 | 数组最大同时运行的元素数 |
| `cores_per_test` | 每组 MPI 进程数 | 每个元素的 MPI 进程数 |
| `nodes` | 整个分配的节点数，每组跨这些节点均分 | 每个数组元素的节点数，每项跨本项节点均分 |
| 授权 CPU 上限 | 并发数 × 每组 MPI 进程数 | 并发数 × 每项 MPI 进程数 |
| 授权节点上限 | 整个分配的节点数 | 并发数 × 每项节点数 |
| `walltime` | 该资源分配的时限 | 每个元素各自的 Slurm 时限 |

受控启动使用每个 MPI 进程一个 CPU、`OMP_NUM_THREADS=1`。数组模式下，6 项并发 × 每项 16 MPI × 每项 1 节点，对应 **96 CPU、6 节点的保守并发峰值**。若每项改为 2 节点，节点峰值为 12，不能用 6 节点授权确认该方案。每项进程数必须能被本项节点数整除。

`时限=04:00:00` 表示每个元素最多运行 4 小时，不是整个收敛阶段必须在 4 小时内结束；不同元素可在不同时间开始。授权峰值、每项节点容量和实际调度可用性是不同检查。资源规划保留每组 MPI 数，只按独立测试数、授权及 CPU/默认内存容量提出候选，仍需操作者确认；不会自动优化科学扫描、NCORE/KPAR 或进行性能试跑，也不保证更快完成。

## 科学扫描保持原清单

每个数组元素对应既有的一个收敛测试目录，ENCUT、k 网格、物理模型、数值阈值和复用证据均保持原规则。实际清单取决于当前任务：

| 元素数 | 既有测试清单 |
|---|---|
| 3 | 复用一类收敛证据，仅执行另一类的三个扫描点 |
| 4 | 三个扫描点，加固定 ENCUT 的一次交叉复核 |
| 6 | 三个 ENCUT 点和三个 k 网格点 |
| 7 | 两类各三个点，再加已配置的固定 ENCUT 交叉复核 |

并发上限为 `min(6, 实际元素数)`；7 项测试最多同时运行 6 项。默认六项仍是两条各三点的扫描，不扩展为 3×3 的九组合扫描。最高 ENCUT 与最密网格对应的两个既有阶段即使输入相同，也保持各自身份，不去重。

脚本只接受有明确并发上限的 `0-N%K` 数组，其中 N 为 0–6，K 为 1–`min(6, N+1)`。六项、六并发的脚本为 `--array=0-5%6`；每项声明 `--nodes=1`、`--ntasks=16`、`--ntasks-per-node=16`、`--cpus-per-task=1`、`--time=04:00:00`，使用受控 `run-array-test` 启动入口。

## 对话与菜单示例

先部署最新计算程序，再在新目录准备任务。示例中的服务器、分区和资源必须适合实际环境：

> 在 eshell111 用 remote_deploy 部署最新版，为 examples/Si.POSCAR 准备新任务 si-array-01，按非磁性三维 PBE 模型和已确认的三点 ENCUT、三点 k 网格方案生成输入，NBANDS=16，先不提交。

按 `/physics eshell111 si-array-01` 完成操作者物理模型确认，再要求 AI 审阅当前阶段输入。随后可以说：

> 提交 si-array-01 已审阅的 convergence 阶段，使用数组模式，最多同时运行 6 项，每项 16 MPI、1 节点，每项时限 4 小时。展示资源菜单，让我确认后继续。

在菜单末行填写：

```text
模式=array 并发=6 每组=16 节点=1 分区=compute 时限=04:00:00
```

填写参数会重新预览，不直接提交。确认预览符合要求后输入 `1`：

```text
资源确认：eshell111 / si-array-01 / convergence
提交模式：array
每个数组元素 16 MPI、1 节点；最大同时运行 6 组；
CPU 并发峰值 96 核；节点并发峰值 6 节点；分区 compute；每项时限 04:00:00。
6 项独立测试分别排队，可能部分先开始运行。
1. 确认以上资源并授权本次阶段提交
2. 保存为默认，并确认本次阶段提交
3. 逐项修改
4. 取消
5. 自定义参数
```

也可输入 `array` / `allocation` 单独切换模式，或使用英文键 `submission_mode=array`。资源变化后必须重新审阅当前快照，通过提交预检后才执行一次 `sbatch`。确认只授权本任务当前阶段的一次提交尝试。默认资源文件可保存模式，不保存提交授权；取消、重启或切换会话不会继承历史授权。

若只需配置，明确要求“将 convergence 资源设为数组模式，先应用，不提交”，使用仅应用资源的菜单；该操作不授权提交。下一阶段仍需独立审阅、资源确认和明确提交要求，资源入口会回到 `allocation`、单组执行。

## 状态、回执与验收

一次数组提交保存父 JobID、元素数量、并发上限和元素 ID 清单。重复请求返回已有回执，不重交；`sbatch` 或传输结果不明确时保留不确定回执，先核对状态。不要把没有返回 JobID 当作未提交。

需要在集群查看展开队列时使用：

```bash
squeue -r -j <父JobID>
```

Agent 的 `remote_status` 同样读取各元素状态。`父JobID_序号` 或压缩显示的 `父JobID_[范围]` 尚在队列时，不能提交后续阶段。父行消失或单独显示 `COMPLETED` 都不足以证明全部完成；必须确认每个预期元素的记账、回执及结果。

最后取得全部元素回执的 worker 会触发统一验收，不额外提交 collector 作业。若超时、取消或进程中断使它未能汇总，按需查询 `remote_status` 会在全部元素确认为终态后调用同一验收器，补做真实输出核验。验收读取 `vasprun.xml`、输入与输出哈希、元素回执、环境及审阅绑定，并执行原有电子收敛和数值收敛检查；Slurm 状态不能代替这些证据。

任一元素失败、超时、输出无效或缺少回执都阻断验收；查询失败、缺少元素记账时状态保持未知或不完整。保留已产生的结果和失败诊断，不自动重交、不自动进入下游。只有全部真实输出验收通过后，才进入等待 `relaxation` 审阅的状态。

## 升级与验证边界

先通过 `remote_deploy` 部署包含数组引擎的最新版。任务绑定的旧 release 不会被替换；旧引擎缺少数组支持时须用新任务目录重新准备。普通已排队、正在运行或已有当前阶段提交记录的作业不能转换模式。现有作业 **71251802** 不在这些示例的操作目标内，不转换、取消或重新提交它。

本功能的回归验证使用 mock Slurm 和合成 VASP 输出，覆盖 3/4/6/7 项清单、资源峰值、失败及结果验收。本文不宣称已经完成真实集群数组运行验证；真实环境的 MPI 连通性、VASP 可执行程序和节点容量仍以该集群证据为准。
