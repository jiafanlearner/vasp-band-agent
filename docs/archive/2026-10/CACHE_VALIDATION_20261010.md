## 模型实验与停止原因

使用一个进程，预设最多 8 个实际 HTTP POST、四对顺序交替的 A0/A1 请求。A0 不带 key，A1 使用同一固定合成会话 key；每对请求的唯一 JSON 差异是 key。工具目录固定为 54 个，指令固定，合成 ASCII 笔记为 40,000 字符，权限状态仅初始化一次；后续预定只追加合成 assistant/user 消息。工具执行被阻止，非流式，输出上限 1,024，阶段超时 90 秒，间隔 2 秒，自动压缩关闭，SDK/model 重试均为 0，没有恢复或线路回退。

实际仅执行第一轮，香港时间 09:40:36–09:40:46：

| 请求 | HTTP | 输入 tokens | 缓存读取 | 缓存写入 | 输出 tokens | 耗时 |
|---|---:|---:|---:|---:|---:|---:|
| A0，无 key | 200 | 21,084 | 0 | 0 | 8 | 4.297 秒 |
| A1，固定 key | 200 | 21,112 | 0 | 0 | 8 | 3.750 秒 |

两条都是完整响应，文本标记正确，无工具调用；原始 HTTP JSON 的用量与 SDK 解析一致。总输入 **42,196**，总输出 **16**，总 tokens **42,212**。这两条响应报告缓存均为 0；首轮快照不能代表后续连续追加命中率。

实际发送正文去掉 key 后的 SHA-256 完全相同，历史 hash 相同；返回 model/tier hash 相同，fixture 没有变化。但是输入 tokens 相差 **28**，使 `input_tokens_equal=false`，第二条的配对控制检查失败。测试停止在第 2 次，没有发送任何第二轮追加请求，没有补齐剩余六次。

**本轮有 2 个有效响应、1 个候选配对、0 个满足全部预设条件的可比较配对。** 原始 matrix 的 `valid` 表示响应/输出/用量核验通过，`paired` 表示候选配对；其旧 summary 的 `paired_rounds=1` 不能解释为实验配对已通过。另存的 `analysis.json` 明确区分这几种计数，原始 matrix 保持不变。

## 证据能够支持的结论

- 这次模型 POST 的 TLS、发送和响应读取均成功。A0 的 trace 为代理 CONNECT → TLS 完成 → 目标 POST 完整收发；A1 没有新建连接/握手事件，本机 stream/TLS 对象 hash 相同，支持本机连接复用。它不证明中转站上游账号、缓存节点或副本相同。
- 当前请求在客户端没有重复指令或改写历史；加入 key 后输入计量不同，是服务响应中观察到的差异，**不能据此证明 key 被当作提示词、服务端发生路由切换或某个 tokenizer 有问题**。
- key 被接口接受并返回 HTTP 200，不证明被转发给真实上游或用于缓存。
- 停止原因是预设输入计量校验，不是本次模型请求超时或 TLS 失败；不能把连接故障与成功响应的缓存零混为一个根因。
- 只有首轮两条，共享前缀可能互相暖缓存，而且使用预定义回复、不含真实 response ID/reasoning。即使后续完成四对，也只能作为小样本合成实验，不能代替正式长会话验收。

这些是假密钥、本地 Mock 的程序行为验收，**不代表真实 API 缓存收益或线路稳定**。修正后没有重跑真实模型；原模型 matrix、现场脚本快照保持不变。
