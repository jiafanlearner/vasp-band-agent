# 指令位置、消息编码与缓存断点实测

日期：2026-10-09，香港时间。本轮按 GitHub 调查继续测试客户端可自行控制的因素，未联系服务商。使用已配置的 relay / https://verysadai.com/v1 / gpt-6-astra / Responses，普通 SDK create、非流式。所有输入为合成测试，54 个工具定义与权限快照保持固定；不执行工具、不访问 SSH、不提交计算，不上传真实会话。

**结果：没有找到稳定改善。基线 A 的四次总输入加权命中率为 38.07%，developer 字符串 B 为 19.52%，typed input_text C 为 34.51%。C 曾到 99.01% 后归零；明确断点被当前接口以 HTTP 400 拒绝。生产默认配置未改。**

## 测试设计

| 组 | 指令形状 | 与哪组比较 |
|---|---|---|
| A | 生产路径的顶层 `instructions` | 基线 |
| B | 同一原文移到首条 developer，content 为 string；删除顶层字段 | A/B 比较位置与包装，不是纯编码对照 |
| C | 与 B 同原文，仅 content 改为 `input_text` 数组 | B/C 比较编码 |
| D | 与 C 只差指令块中的 `prompt_cache_breakpoint={"mode":"explicit"}` | D/C 比较明确边界，不添加 key、不强制 explicit mode |

每组精确重放完整请求，不追加上一轮回答。ABC 顺序预先固定为 ABC、BCA、CAB、ACB，原计划各 4 次。请求之间暂停 15 秒，SDK/model 重试为 0，输出上限 1,024，自动压缩关闭。记录实际 HTTP 正文哈希、参数哈希、HTTP 状态、请求 ID、原始 usage 安全子集及 SDK 解析用量，不保存认证头、密钥或响应正文。

SDK 序列化的离线 MockTransport 检查通过：指令原文仅出现一次、调用者的历史未修改、B/C 只改变编码、C/D 只多断点字段。完整生产指令和 54 项 schema 的另一次离线审阅也未发现重复拼接。当前缓存相关回归运行 21 项通过，非全量回归。

第一批在 B 的第二次请求读取超时后停止。暂停后补测，统一使用 90 秒超时；复用第一批的合成结构与工作区，指令/工具/历史三个哈希一致。补测断点组缩为 2 次，另设同一时段 C 对照 2 次，本轮总尝试上限仍为 20。两批分别统计，不通过删除失败或挑最高单轮来报告成功。

主指标为有效响应的总缓存 tokens / 总输入 tokens；首次和预先规定的第 2–4 轮分开记录。字段缺失保留为未知，不当作零。首轮可能已被之前流量或其他组暖缓存，不能称冷启动。短小实验不足以证明长期稳定。

typed 方案没有稳定命中，且再次复现“同正文高命中后归零”：

D 首次请求耗时 2.297 秒，HTTP 400，没有返回 usage，也没有 request ID。脱敏错误字段：

```json
{"type":"invalid_request_error","code":"invalid_parameter","param":"prompt_cache_breakpoint"}
```

安全分类同时确认错误消息提及断点和 unsupported/unknown 类描述；不保存完整服务商错误正文。结合 C 请求成功、D 仅多断点，该接口当前拒绝这一断点形状。不能将它理解为中转站所有缓存功能均不支持；未删除参数自动重发、未改模式或服务商。

## 判断边界

相同指令原文放在顶层时返回 9,329 输入 tokens，移入 developer 后 B/C 均为 13,445，多 4,116。离线没有重复拼接；服务侧包装/计量差异尚未确定。因此 A/B 不能称等量输入，更不能仅按命中百分比宣布节费；需要比较未缓存 tokens。B/C 仍可作为相同输入计量的编码对照。

这组 B/C 中 typed 的累计命中高于 string，但没有通过预设的“后 3 轮均至少 90%”筛选，仍发生归零，且仅 4 轮，不能宣布编码是稳定修复。相对 A，B/C 还增加输入总量；本次未缓存输入也更多，不能据此迁移正式会话或宣称降费。

当前保留顶层 instructions，断点保持关闭。下一阶段若继续调查，可单独测试固定缓存 key、流式或推理设置；每个都应有自己的对照，不能同时开启后归因。更直接的工程收益是减少无用输入和重复工具输出，并保留 raw usage、正文指纹及错误证据。尚未证明问题的确切根因，无需因为此次测试去重置会话、改密钥或联系管理员。

明确断点的放置依据官方文档：顶层 instructions 不能包含断点，developer 的 input_text 支持该字段。HTTP 200 只能说明请求被接受，不能证明中转站将字段传给上游或启用了缓存；HTTP 400 也须结合安全错误字段判断，不能泛化为全站不支持缓存。[官方说明](https://developers.openai.com/api/docs/guides/prompt-caching)
