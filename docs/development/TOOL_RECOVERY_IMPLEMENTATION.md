## 后续修复：参数菜单被空行跳过

用户报告未主动按回车，但菜单直接进入 pending。代码检查发现主对话使用 PromptSession，而交互菜单直接使用 builtins.input，且参数选项把空行立即解释为取消。尚未在用户实际终端重现当时的输入字节来源，不能断言具体是哪一次粘贴产生了空行。

- `terminal_ui.py` 新增 `read_menu`，已有 PromptSession 时共享同一输入后端，菜单禁用斜杠补全及工具栏；普通输入模式保留 input 回退。
- `ai_agent.py` 将参数工具及交互命令的 reader 绑定到 UI 的菜单输入入口。
- `parameter_plans.py` 的 1/2/3/4 选择菜单遇到空白继续等待；仅 4/q 明确暂不决定，不默认选择、不消耗提交授权。EOF 保留待选状态并退出，不循环吞掉 EOF。
- 更新使用说明与测试。新增覆盖带末尾换行的 bracketed paste 后切换菜单、普通输入回退、多个空行后明确选择或取消、EOF，以及 Agent.ask 中建议菜单先读到残留空行的情形。

全量离线验证：`python -m pytest -q` → **194 passed，15 个 spglib 弃用警告**。本次使用 apply_patch 修改文件，未连接集群、部署或提交任务。重启本机 Agent 后可用 `/plan` 继续已有 pending 草案，无需新建对话或删除草案；实际 Git Bash 终端行为仍需用户验证。

## 回归修复：菜单提示污染主对话输入

上次共享 PromptSession 的改动遗漏了设置恢复。PromptSession.prompt(message=..., bottom_toolbar=...) 会持久修改实例属性；completer=None 参数实际上表示保持原值，并不能禁用补全。这导致 /sessions 已结束后仍显示“输入编号切换”，用户后续输入编号被当成普通聊天文本。

`terminal_ui.py::read_menu` 现在保存 message/completer/bottom_toolbar/key_bindings，直接设置菜单专用值，并通过 finally 完整恢复；菜单正常完成、Ctrl+C 和 EOF 均恢复主输入的提示、补全、工具栏和按键设置。

新增 4 项测试。先在修复前复现正常返回及中断后的提示残留，再验证修复。完整路径使用真实 PromptSession 和管道输入执行 /sessions → 选择对话 → 主输入 /plan ID → 选择参数 → 主输入 /history，检查实际运行时提示与补全设置，禁止调用模型，不创建计算任务。

完整离线回归：`python -m pytest -q` → **198 passed，15 个 spglib 弃用警告**。未连接集群、部署或提交。用户需重启本机进程后验证 Git Bash 显示；不需要 /new、删除草案或更改远程引擎。
